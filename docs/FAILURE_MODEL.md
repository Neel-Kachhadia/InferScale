# Failure model and current coverage

Backend results use `RequestRecoverable`, `EngineRecoverable`, `EngineRestartRequired`, and `ProcessFatal`. Input/ticket validation and pinned llama decode statuses are translated to controlled request or engine failures; unknown exceptions are process-fatal. Fatal CUDA/model recovery and automatic restart are not claimed or tested in this phase.

A request failure, deadline, cancellation, or shutdown records terminal intent first. The reactor stops scheduling for that `RequestKey`, retains issued-ticket pins, suppresses stale output, and queues a backend clear only after every ticket retires. Sequence reuse then waits for llama synchronization, successful `llama_memory_seq_rm`, and a matching clear acknowledgement. A clear failure leaves the slot quarantined and transitions the service unhealthy.

The model-backed cancellation test closes the client during a long prefill; a subsequent request succeeds. The model-backed slow-reader test uses 186 bytes of test output capacity and a 1024-byte send buffer, leaves the SSE response unread, reaches the five-second write timeout, and then verifies the same model service can complete a new request. The active-shutdown test sends SIGTERM after receiving a real generated piece; the stream closes, in-flight ownership retires, and CUDA allocations are released. Runtime unit/integration tests retain deterministic FakeEngine barriers and generation/ticket race checks.

The TSan-instrumented suite's default runtime binary aborted before `main` with `ThreadSanitizer: unexpected memory mapping` on this Linux 7.0.0-38 / GCC 13.3 host. With the per-process workaround `setarch x86_64 -R ctest --test-dir build/tsan --output-on-failure`, all 28 runtime tests and the HTTP integration passed. No system ASLR setting was changed. Boost.Asio emitted its expected warning that `atomic_thread_fence` is not modeled by TSan; report this suite as passed with that host launch limitation.

Remaining valid future work: compact generation-history state for an unbounded long-lived process; move vocabulary tokenization off the HTTP I/O thread if contention warrants; return a more specific HTTP status for over-context/admission rejection; and add a backend restart/fatal-recovery campaign in its assigned later phase.
